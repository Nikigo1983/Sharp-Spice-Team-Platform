# CRM Client Creation Rules (рекомендации)

**Дата:** 16 июня 2026  
**Режим:** только анализ и рекомендации, без внедрения  
**Основа:** `FORMGRID_DATA_QUALITY_REPORT.md` (live срез Formgrid, 11 лидов)

---

## Цель

Определить, какие поля сделать обязательными для кнопки **«Создать клиента в CRM»**, чтобы:

- не терять клиентов из-за слишком жёстких правил;
- не создавать проблемные записи с ошибками данных;
- сохранить достаточное качество для дальнейшего UCI/dedup.

---

## 1) Варианты обязательных полей

### Вариант A — Минимум

**Обязательное поле:**

- Паспорт

**Плюсы:** максимальная проходимость, быстрый импорт.  
**Минусы:** риск низкого качества карточек (нет ФИО/контактов), сложнее работа менеджера.

---

### Вариант B — Средний

**Обязательные поля:**

- Паспорт
- ФИО

**Плюсы:** сохраняется идентичность + читаемая карточка клиента.  
**Минусы:** можно создать клиента без рабочего контакта.

---

### Вариант C — Строгий

**Обязательные поля:**

- Паспорт
- ФИО
- Телефон
- Email

**Плюсы:** максимально качественная карточка, сильный контактный профиль.  
**Минусы:** повышенная блокировка лидов, если любой контактный канал отсутствует/битый.

---

## 2) Проход по текущим 11 лидам

Использованы факты из аудита:

- Паспорт: **11/11**
- ФИО: **11/11**
- Телефон валиден: **10/11**
- Email валиден: **11/11**

### Результаты по вариантам

| Вариант | Обязательные поля | Пройдут | Заблокируются |
|---------|-------------------|---------|---------------|
| A (Минимум) | Паспорт | **11 / 11** (100%) | **0 / 11** |
| B (Средний) | Паспорт + ФИО | **11 / 11** (100%) | **0 / 11** |
| C (Строгий) | Паспорт + ФИО + Телефон + Email | **10 / 11** (90.9%) | **1 / 11** |

---

## 3) Кейс: Белкания Автандил Яношевич

**Данные из аудита:**

- ФИО: есть
- Паспорт: есть (`77 5045756`)
- Телефон: `#ERROR!` (невалидно)
- Email: валиден (`Name.dilon7711@gmail.com`)

### Можно ли создавать такого клиента?

| Правило | Решение |
|---------|---------|
| A (Паспорт) | Да |
| B (Паспорт + ФИО) | Да |
| C (Паспорт + ФИО + Телефон + Email) | **Нет** |

### Риски, если создать без валидного телефона

1. Невозможно быстро связаться с клиентом по основному каналу.
2. Ошибочные значения (`#ERROR!`) попадут в CRM-процессы и отчётность.
3. Хуже дедуп/проверка контактов в будущем (особенно при ручных сопоставлениях).

### Рекомендация по этому кейсу

- **Не автосоздавать**, пока телефон не исправлен.
- Оставить лид в очереди с причиной блокировки: `некорректный телефон`.
- Разрешить только ручной override менеджером при явной бизнес-необходимости.

---

## 4) Финальная рекомендация для кнопки «Создать клиента в CRM»

### Рекомендуемый базовый набор обязательных полей

- **Паспорт**
- **ФИО**
- **Телефон (валидный)**

Email — сделать **неблокирующим**, но проверять и подсвечивать.

### Почему не A/B

- A/B пропускают записи с явными ошибками контакта (как `#ERROR!`), что ухудшает качество CRM.

### Почему не полностью строгий C

- В текущем срезе C тоже даёт 10/11, но в реальной операционке email чаще бывает пустым/неактуальным, и это может неоправданно блокировать лидов.
- Телефон в этом процессе практичнее как обязательный контактный канал.

---

## Рекомендованное правило (итог)

**Create in CRM = разрешить, если:**

1. `passport` валиден (после нормализации длина >= 6),
2. `name` не пустой,
3. `phone` валиден (>= 7 цифр, не `#ERROR!`).

**Email:**

- если валиден — записывать;
- если пустой/невалидный — не блокировать, но показывать предупреждение менеджеру.

---

## Что это даст на текущих данных

- Проход: **10/11 (90.9%)**
- Блокировка: **1/11** (только проблемный телефон)
- Баланс: высокое качество + минимальная потеря лидов
