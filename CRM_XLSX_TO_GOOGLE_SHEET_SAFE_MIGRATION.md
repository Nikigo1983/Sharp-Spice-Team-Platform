## 1. Что произойдёт при конвертации XLSX → Google Sheet

### 1.1. Spreadsheet ID (File ID в URL)

| Сценарий | Сохранится ли ID `138W2nHQcJu…`? |
|----------|----------------------------------|
| **In-place конвертация** в Drive (тот же файл, меняется только тип) | **Часто да** — Google может оставить тот же File ID |
| **«Сохранить как Google Таблицу»** → создаётся **новый** файл | **Нет** — новый ID в URL |
| **Вариант B** (новая таблица + импорт) | **Нет** — всегда новый ID |

**Практическое правило:** после любой операции **скопировать ID из адресной строки** и сравнить с `138W2nHQcJu_xRsI2RBqeD6Oq8Tg9FbKH`. Не предполагать, что ID сохранился.

### 1.2. `gid` вкладки External

| До миграции | После миграции |
|-------------|----------------|
| `1431336126` (лист внутри `.xlsx` на Drive) | **Почти наверняка другой** numeric `gid` |

`gid` — идентификатор **листа внутри документа**. При смене формата файла или создании новой таблицы Google **переназначает** `gid`.

**Следствие для платформы:** `GOOGLE_SHEETS_PUBLIC_CLIENTS_GID` **нужно обновить** после миграции, даже если Spreadsheet ID не изменился.

Проверка после миграции:

```
https://docs.google.com/spreadsheets/d/{SPREADSHEET_ID}/export?format=csv&gid={NEW_GID}
```

### 1.3. Формулы, форматирование, фильтры

| Элемент | При конвертации / импорте |
|---------|---------------------------|
| **Формулы Excel** | Могут **сломаться** или замениться на аналоги Sheets; сложные макросы VBA **не переносятся** |
| **Форматирование** | В основном сохраняется (цвета, шрифты, ширина колонок) — с расхождениями |
| **Условное форматирование** | Частично сохраняется |
| **Фильтры / сортировка** | Могут сохраниться на листе; **проверить вручную** |
| **Объединённые ячейки** | Сохраняются, но могут влиять на CSV export |
| **Формат «Текст» для паспортов** | **Критично:** без формата «Текст» паспорта могут стать числами (`7.66E+08`) → слом `Client.id` и dedup |

**Для External:** перед cutover выделить колонку «Номер паспорта» → **Формат → Текст** (или импорт с «форматировать как текст»).

### 1.4. Public CSV export

| Вопрос | Ответ |
|--------|--------|
| Работает ли export на native Google Sheet? | **Да** — тот же URL-шаблон |
| Сохранится ли без изменений? | **URL-шаблон да**, но **параметры `ID` и `gid` могут измениться** |
| Нужны ли права доступа? | Файл должен быть доступен для export (как сейчас для `.xlsx`: обычно «все по ссылке» или доступ команды) |
| Изменится ли содержимое CSV? | Должно совпадать по данным; риск — **формат чисел/дат** и лишние кавычки |

Платформа читает CRM через:

```text
/docs.google.com/spreadsheets/d/{ID}/export?format=csv&gid={GID}
```

(`google-sheets-client.ts` → `fetchPublicClientsCsv`)

После миграции **парсер не меняется** — меняются только ENV `ID` + `gid`.

### 1.5. Google Sheets API (запись — будущая фаза)

| До (`.xlsx`) | После (native Sheet) |
|--------------|----------------------|
| `spreadsheets.get` → **400 Office file** | **200 OK** |
| `values.append` → недоступен | **Доступен** при роли Editor у SA |

Миграция **разблокирует** API, но **не включает** запись автоматически — нужны код + `GOOGLE_SHEETS_CLIENTS_RANGE=External!A:M`.

## 2. Самый безопасный вариант: A vs B

### Вариант A — Конвертировать текущий файл

**Суть:** открыть `таблица Клиенты Хорватия.xlsx` через Google Таблицы и конвертировать **на месте** (или «Сохранить как Google Таблицу» в том же Drive).

| | |
|--|--|
| **Плюсы** | Меньше ручного копирования; иногда **тот же Spreadsheet ID**; одна «главная» ссылка для команды (если ID сохранился) |
| **Минусы** | **Меняется боевой файл** — ошибка конвертации бьёт по production; откат сложнее; `gid` всё равно меняется; риск испортить паспорта/даты; если создаётся **новый** файл — путаница «какой из двух главный» |
| **Риски** | Потеря формул; scientific notation на паспортах; downtime при срочном откате; команда продолжает редактировать старый `.xlsx`, пока вы конвертируете |
| **Откат** | **Сложный:** восстановить из backup `.xlsx`, вернуть старый `gid` в ENV; если файл перезаписан — только из копии Drive |
| **Подходит если** | Команда уверена в конвертации, есть свежий backup, готовы проверить ID/gid/93 строки за 30 минут |

### Вариант B — Новая Google Таблица + перенос (рекомендуется)

**Суть:** создать **новый** файл `Клиенты Хорватия (Google Sheets)` → импортировать данные из backup `.xlsx` → проверить → переключить ENV → старый `.xlsx` **не трогать** (read-only архив).

| | |
|--|--|
| **Плюсы** | **Боевой файл не меняется** до cutover; **простой откат** (вернуть старые ENV); можно тестировать новую таблицу неделю на preview; явное именование листа `External`; параллельная работа менеджеров в старом файле до переключения |
| **Минусы** | **Новый Spreadsheet ID** — обязательно менять ENV; ручная сверка 93 строк; новая ссылка для закладок; повторно расшарить SA (Editor) |
| **Риски** | Пропуск строк при импорте; расхождение если менеджеры правят **оба** файла до cutover; забыть обновить хардкод в `relocation/forms.ts` |
| **Откат** | **Простой:** production ENV → старый ID + `gid=1431336126`; новая таблица удаляется или игнорируется |
| **Подходит для** | **Production** — минимальный риск для текущих данных |

### Сравнительная таблица

| Критерий | A — конвертация | B — новая таблица |
|----------|-----------------|-------------------|
| Безопасность боевых данных | Средняя | **Высокая** |
| Откат за &lt; 5 мин | Сложно | **Да** (ENV) |
| Смена Spreadsheet ID | Может не потребоваться | **Обязательно** |
| Смена `gid` External | **Да** | **Да** |
| Downtime при cutover | 15–60 мин | **5–15 мин** (только ENV) |
| Параллельная подготовка | Нет | **Да** |
| **Рекомендация** | Запасной | **Основной** |

## 3. Влияние на платформу (ENV)

### 3.1. Обязательно обновить при cutover (чтение)

| ENV | Сейчас (пример) | После миграции | Когда |
|-----|-----------------|----------------|-------|
| `GOOGLE_SHEETS_SPREADSHEET_ID` | `138W2nHQcJu_xRsI2RBqeD6Oq8Tg9FbKH` | **Новый ID** (B) или тот же (A in-place) | Cutover |
| `GOOGLE_SHEETS_PUBLIC_CLIENTS_GID` | `1431336126` | **Новый gid** External из URL | **Всегда** |

### 3.2. Обновить перед фазой записи (не в день миграции данных)

| ENV | Сейчас | После |
|-----|--------|-------|
| `GOOGLE_SHEETS_CLIENTS_RANGE` | `Clients!A1:Z2000` (fallback) | **`External!A:M`** |

### 3.3. Не менять при CRM-миграции

| ENV | Причина |
|-----|---------|
| `GOOGLE_SHEETS_FORMGRID_SPREADSHEET_ID` | Отдельный файл Formgrid |
| `GOOGLE_SHEETS_FORMGRID_GID` | Formgrid |
| `GOOGLE_SHEETS_FORMS_RANGE` | Вкладки нет в текущем CRM |
| `GOOGLE_SHEETS_DOCUMENTS_RANGE` | Не используется в production |
| `GOOGLE_SHEETS_NOTES_RANGE` | Заметки в Supabase, не Sheets |
| `GOOGLE_SERVICE_ACCOUNT_EMAIL` | Тот же SA |
| `GOOGLE_PRIVATE_KEY` | Тот же ключ |
| `GOOGLE_SHEETS_CACHE_TTL_MS` | Опционально |
| `EMIGRANT_*`, `SUPABASE_*` | Не связаны с CRM файлом |

### 3.4. Зависимости в коде (обновление после cutover — отдельный PR)

| Файл | Что привязано |
|------|----------------|
| `src/lib/relocation/forms.ts` | `CROATIA_CLIENTS_SHEET_URL`, `CROATIA_CLIENTS_SHEET_ID`, `gid=1431336126` |
| `.env.example` | Документация (опционально) |

Остальной код читает CRM **только из ENV** — деплой не обязателен для cutover, если обновить Vercel ENV.

### 3.5. Что сломается, если обновить ENV неправильно

| Симптом | Причина |
|---------|---------|
| Пустой `/clients` | Неверный `gid` или ID |
| Lead Review: нет strong dup | CRM «пустой» для dedup |
| AI: 0 клиентов | То же |
| Аналитика Хорватия: нули | То же |
| Sheets append (будущее): 404 | Неверный range `Clients!` вместо `External!` |

## 4. Влияние на пользователей (менеджеров)

### 4.1. Изменится ли ссылка?

| Вариант | Ссылка для менеджеров |
|---------|------------------------|
| **A** (in-place, тот же ID) | **Может не измениться** — но `gid` в URL при открытии вкладки External **изменится** |
| **B** | **Да, новая ссылка** на Google Таблицу |

Платформа: раздел **Эмиграция** ведёт на **хардкод** старого URL (`relocation/forms.ts`) — после cutover нужен PR или ручное обновление ссылки в UI.

### 4.2. Нужна ли новая ссылка?

| Кто | Действие |
|-----|----------|
| Менеджеры, работающие **в Google Таблице напрямую** | **Да** — обновить закладку после cutover (B) или проверить вкладку External (A) |
| Менеджеры, работающие **только через платформу** (`/clients`) | **Нет** — достаточно ENV на сервере |
| Service account | Расшарить **новый** файл (B) ролью **Редактор** |

### 4.3. Можно ли оставить старую таблицу как backup?

**Да — обязательно рекомендуется.**

| Роль старого `.xlsx` | Настройка |
|----------------------|-----------|
| Архив read-only | Переименовать в `… — ARCHIVE (не использовать)` |
| Права | Убрать редактирование у команды или оставить только владельцу |
| Production | **Не** указывать в ENV после cutover |

Держать архив **минимум 30 дней** после успешного cutover.

### 4.4. Можно ли без остановки работы?

**Да** — схема **blue-green**:

```
Фаза подготовки (дни/недели):
  Боевая CRM (.xlsx) ← production ENV ← платформа работает
  Новая native Sheet ← тестируется вручную + Vercel Preview ENV

Cutover (5–15 минут):
  1. Заморозить правки в старом файле (договорённость с командой)
  2. Финальная синхронизация diff (если были правки после импорта)
  3. Обновить production ENV (ID + gid)
  4. Smoke: /clients, 3 клиента, Lead Review dup
  5. Объявить новую ссылку на таблицу

Откат при проблеме:
  Вернуть старые ENV → платформа снова на .xlsx
```

**Важно:** если менеджеры правили **оба** файла до cutover — возможен drift. На cutover либо freeze на старом, либо одноразовый diff-merge.

## 6. Итоговый вердикт

### Рекомендуемый вариант: **B**

**Почему:**

1. Боевой `.xlsx` **не изменяется** до осознанного cutover.
2. **Откат = вернуть ENV** за минуты.
3. Можно **неделю** тестировать новую таблицу на Preview без риска для production.
4. Параллельно готовить код записи (`LEAD_REVIEW_CRM_WRITE_IMPLEMENTATION_PLAN.md`).

**Вариант A** допустим только при жёстком требовании сохранить тот же File ID **и** готовности команды к быстрой сверке; откат всё равно сложнее.

### Основные риски

| Риск | Митигация |
|------|-----------|
| Потеря/искажение паспортов | Формат «Текст»; сверка 10+ паспортов |
| Неверный `gid` в ENV | Копировать из URL после открытия External |
| Drift двух файлов | Freeze старого перед cutover |
| Менеджеры на старой ссылке | Коммуникация + обновление Эмиграции |
| Раннее включение append | Шаг 8 только test row; write — отдельный PR |

### Что сделать вручную в Google Drive

1. Создать **backup-копию** `.xlsx`.
2. Создать **новую** Google Таблицу.
3. **Импортировать** External из backup.
4. Проверить **93 строки**, формат паспортов.
5. Расшарить на **service account** (Editor).
6. Записать **новый ID** и **новый gid**.
7. После cutover — переименовать старый файл в **ARCHIVE**, ограничить редактирование.
8. Разослать команде **новую ссылку**.
